# OpenCode Native Chat

## Boundaries

- Work only in this project; `combinezone` is a different repository. Communicate with the user in Russian.
- The goal is an extension with native Chat through `chatSessionsProvider` and ACP. Webviews, a separate chat, VS Code core patches, and the built-in Agent Host are outside the chosen architecture.
- Use Node >=22.19. For a clean checkout, run `npm ci`; before launching the editor through the CLI, run `npm run build`. TypeScript 7.0.2/esbuild and Effect Machine devtools 0.40.0 are dev dependencies; Effect 4.0.2, Effect Machine 0.40.0, SDK 1.7.0 and zod 3.25.76 are runtime dependencies. esbuild bundles runtime ESM into CommonJS; devtools and its transitive TypeScript 6/platform tooling stay dev-only. Agree on new dependencies with the user.
- Verify proposed API contracts against the public source of **the editor version being tested**, not `main` or files from the local VS Code installation. Links for 1.140.0 are in README.

## Request path

- `src/main.ts` is the thin entry point with a runtime `vscode` import; `src/extension.ts` handles the native adapter, scoped permissions Quick Pick, and serialized metadata in `workspaceState`; `src/session-options.ts` handles inline groups/bindings; `src/session-commands.ts` handles slash customizations/virtual files; `src/command-templates.ts` and `src/session-files.ts` handle Effect preparation/IO; `src/sessions.ts` handles synchronous admission, registry, and current projections; `src/machines/connection.ts`, `session.ts`, and `turn.ts` own logical connection, session load/config/history, and turn/permission/cancel orchestration through lazy services. `src/protocol.ts` owns raw guards/catalog projections. `src/acp.ts` retains physical process/failure/deadline/resource policy with stable SDK `client()` / `ndJsonStream()`; NDJSON, JSON-RPC IDs, and correlation remain SDK-owned.
- When changing orchestration, read docs/development.md, "Effect runtime and machine ownership", and docs/plans/effect-migration.md. Preserve explicit application/generation/turn Scope ownership and the custom native Scope runner (not ManagedRuntime). Promise facades are compatibility boundaries. Reserve synchronously before dispatch; register correlated Deferred completion first, not send/waitFor acknowledgement. Read current projections for guards; commit config/revision before events/completion and check generation/operation identity. UI binding disposal does not stop backend sessions; terminal disposal forbids reconnect. Machine snapshots are not persisted for recovery.
- When changing the ACP boundary, preserve fail-closed behavior and raw unknown guards before SDK optional normalization. The protocol-error guard reads only SDK byte output; the envelope guard reads already-parsed messages. SDK types do not replace runtime validation; read docs/development.md, "Transport and limits", for the byte limit and bounded EOF.
- The editor loads `dist/main.js`; unit tests import `dist/extension.js`, `dist/sessions.js`, `dist/acp.js`, and `dist/machines/*.js`. Generated bundles/sourcemaps, `node_modules/`, and `.effect-machine/` are excluded from Git; edit source files, not generated output.
- Launch `opencode acp` with `shell: false`, not an HTTP client for a shared service. `opencodeNativeChat.command` is an executable path, not a command string with arguments. Preserve ACP v1, `clientCapabilities: {}`, and `mcpServers: []` for new/load.
- The participant ID, session type, and URI scheme must match: `opencode`. The extension ID for the CLI is different: `RabbitShare.opencode-native-chat` (`publisher.name` from `package.json`).
- The native participant routes Send to the same `requestHandler` as the content provider. When changing routing, check both saved resources and `opencode:/untitled-*` for the first request.
- OpenCode stores history and replays it through `session/load`; `workspaceState` stores only `id`, `cwd`, `label`, and `created`. The extension's list does not import all OpenCode sessions.
- Catalogs/confirmed selections for Model (`model`), Agent (`mode`), and Reasoning (`effort`) come from ACP new/load/set/update; pass literal values without splitting IDs or hardcoded choices. LanguageModelChat **OpenCode (configured)** is only a technical bridge, not the actual selection. Skills, MCP, and permissions remain with OpenCode. Preserve atomic raw validation before SDK normalization; a malformed update does not change the snapshot, and absent/null new/load means an empty catalog. Hide Reasoning when there are no effort choices; do not replace an unavailable currentValue with a fallback.
- The slash catalog comes from ACP `available_commands_update`, separately for each session; a malformed/over-limit update does not change the snapshot, and failure/load clears the stale list. `chatSessionCustomizationProvider` returns Prompt items only for the exact canonical REAL URI or an already-materialized alias. Generic drafts remain lazy. Virtual `opencode-command:` files contain only metadata; external/foreign/stale prompt references are rejected before the prompt, with another synchronous check after config/load waits and before history/RPC. Read docs/development.md, "Slash commands", for catalog limits, native names/collisions, and the checklist. Do not replace ACP commands with hardcoded TUI commands.
- File context included in the submitted request, both explicit and implicit, is sent as ACP embedded text resources. Preserve current unsaved text and exact Location ranges, the file scheme/ID guards, negotiated embeddedContext, and bounds. Read only referenced documents inside the reserved prompt slot after config/load/template waits; reference failure performs no file IO, and preparation failure adds no history/RPC. Keep slash metadata validation separate. See docs/development.md, "Slash commands", for file-context limits and native sources.
- In 1.140.0, the catalog is shared by session type; there is no separate per-resource catalog API. Preserve the union of unique groups for live REAL URIs: own selections are defined, foreign ones undefined; the provider returns its own `ChatSession.options`. The hidden locked `opencode_session` marker with `when: "false"` and `unconfigured` filters REAL groups through `chatSessionOption.opencode_session`. A binding belongs to the original URI; revision-scoped item IDs and observed/pending state suppress broadcast/echo and do not use the active panel/marker to select a backend record. When changing UI, read docs/development.md, "Model / Agent / Reasoning", for the current contract and native checklist; doubles do not prove reused/resource-less renderer isolation.
- The setter synchronously reserves one pending slot and checks revision/membership; an active/reserved prompt prohibits changes. Send waits for an already-accepted config operation; its failure adds no turn and sends no prompt. Stop before the prompt starts sends no cancel and does not cancel the setter. An RPC error/malformed set makes config uncertain; a fresh load is required before a future prompt, without automatically replaying old selections/tools/permissions. Preserve lock refresh after reservation and turn cleanup.
- Product New (`opencode.newSession`) selects cwd, creates one empty saved ACP session, opens the REAL URI through public `vscode.open`, then moves the same session to the sidebar through `workbench.action.chat.openInSidebar`; the original tab closes, and generation occurs only on Send. Move in 1.140.0 uses the active Chat editor; see README for native verification of moving/focus changes. The generic draft/new-item handler and untitled route remain lazy/default until materialization; activation and an undefined input query do not launch ACP.
- The top "+" in OpenCode Chat routes to Product New through the proposed `chat/newSession` menu: `1_open@0`, `chatSessionType == opencode`, Trust and workspace gating. Other session types and explicit generic draft commands retain the standard lazy route; do not launch ACP in an undefined input-state query for the sake of a picker. Verify the native primary action separately from the manifest/adapter double.
- One process serves multiple sessions; each session allows one active prompt. The deadline for an ordinary ACP request is 30 seconds; prompts have no overall deadline. A timeout closes the shared connection and process, affecting other sessions. Stop after the prompt starts sends async `session/cancel` with rejection handling; after 5 seconds, a hung connection is also closed for all its sessions.
- Keep prompt invocation on TurnMachine's Active parent, with Running/Cancelling children: Stop retains the correlated SDK await. Session-owned single-flight load and an accepted setter survive Stop of a waiting turn; all joined load callers receive success/failure. Permissions are independently correlated; cancellation/failure closes pending pickers and never accepts late/empty choices.
- Preserve Workspace Trust and explicit permission choices: Escape, closing Quick Pick, and cancellation do not approve a tool. The client does not declare filesystem/terminal capabilities; the extension is not a sandbox.

## Checks

- After runtime changes: `npm test` and `npm run check`. `pretest` builds bundles; `precheck` builds them and runs `npm run check-types` (strict, no emit). Check verifies syntax and manifest/launch/tasks, but not editor compatibility.
- After machine changes: `npm run visualize:build`; inspect `.effect-machine/site/machines.json` for ConnectionMachine, SessionMachine and TurnMachine Ready without diagnostics. `npm run visualize` runs the official loopback devtools. Read docs/development.md, "Machine visualizer and topology simulation", before using it: evaluation imports trusted modules, not a sandbox; keep machine imports free of IO/runtime vscode. Simulation is topology-only, runs no effects/guards/resolvers, and has no live runtime connection. It never replaces runtime/native verification.
- Before running tests directly, run `npm run build`. One file: `node --test test/extension.test.js`; one scenario: `node --test --test-name-pattern='session-type participant' test/extension.test.js`. Put runner flags before the file path.
- The user temporarily prohibited edit/Retry after the migrations: `supportsCheckpoints` remains absent/false; the shared handler rejects native Retry and inconsistent history before an ACP prompt. Approved native capabilities are `supportsPromptAttachments: true` and `supportsFileAttachments: true`; other attachments remain disabled. Preserve regressions for the prohibition, ordinary new Send, and included file context. The historical replacement baseline was replaced with checks for the chosen contract; read docs/development.md, "Checks", for verification history and previous deadline failures under load. Replacement/fork remains a separate stage; selectors/slash commands/files do not bypass the prohibition.
- Unit tests launch a real child process, `test/fixtures/agent.cjs`, without a model, credentials, or an installed OpenCode. They replace the VS Code API with a double; this is not native UI evidence.

## Editor verification

- For manual verification, use the **OpenCode Native Chat** configuration in `.vscode/launch.json` or the CLI command from README with `--enable-proposed-api=RabbitShare.opencode-native-chat`. Both F5 configurations run **build extension** before launch; after editing, rebuild bundles first, then run **Developer: Reload Window**. Changes to runtime arguments require a full editor restart.
- Run manual checks without `--extensionTestsPath`; isolate them with `--user-data-dir` and `--extensions-dir`. Artifacts in `test/.editor-profile/` and `test/.editor-extensions/` are excluded from Git; logs may contain prompts and secrets.
- **Native API smoke test** checks activation and lazy draft open through `workbench.action.chat.openNewChatSessionInPlace.opencode` with `sidebar`, not eager Product New: no ACP or prompt. CLI extension tests use in-memory storage; the smoke test waits up to three minutes for manual Workspace Trust. Do not disable Trust or set it programmatically.
- In VS Code 1.140.0, `activeChatPanelSessionResource` returns only Local sessions. Confirm that OpenCode opened through the renderer log: `ChatWidget#firstRender: session=opencode:/…` and `[ChatViewPane] loadSession done … uri=opencode:/…`.
- `supportsAutoModel: true` unblocks Send but **does not remove** the `LanguageModelChat` requirement when converting a request in VS Code 1.140.0. `Language model unavailable` occurs before the ACP handler; do not try to fix it by reconfiguring OpenCode credentials.
- Backend responses and fixture tests do not prove native Send. An editor response, incremental streaming, real tools, approval/rejection, Stop during a response, and recovery after restart require separate observations; do not claim that the smoke test verifies them.
- Manual confirmations in docs/development.md include previous builds before and after the TypeScript/SDK migrations. Model/Agent/Reasoning and eager New have an incomplete separate checklist; Effect bundles and the modified smoke test need separate native verification. Preserve historical results and verify new bundles separately. Automated GREEN does not mean release/review approval.
