# OpenCode Native Chat

## Boundaries

- Work only in this project; `combinezone` is a different repository. Communicate with the user in Russian.
- The goal is an extension with native Chat through `chatSessionsProvider` and ACP. Webviews, a separate chat, VS Code core patches, and the built-in Agent Host are outside the chosen architecture.
- For a clean checkout, run `npm ci`; before launching the editor through the CLI, build the extension with `npm run build`. TypeScript/esbuild are dev dependencies; the runtime pair is SDK 1.7.0 and zod 3.25.76. esbuild includes the ESM SDK and its `zod` peer in CommonJS bundles. Agree on new dependencies with the user.
- Verify proposed API contracts against the public source of **the editor version being tested**, not `main` or files from the local VS Code installation. Links for 1.140.0 are in README.

## Request path

- `src/main.ts` is the thin entry point with a runtime `vscode` import; `src/extension.ts` handles the native adapter, permissions Quick Pick, and metadata in `workspaceState`; `src/session-options.ts` handles inline config groups, live bindings, and the input-state lifecycle; `src/session-commands.ts` handles native slash customizations and read-only virtual prompt files; `src/sessions.ts` handles the ACP lifecycle, confirmed config/revision/`config` event, command catalog/`commands` event, history, permissions, and cancellation; `src/protocol.ts` handles raw guards and catalog projections; `src/acp.ts` is the process adapter using stable SDK `client()` / `ndJsonStream()`. NDJSON parsing/serialization, JSON-RPC IDs, and correlation belong to the SDK; process/failure/deadline/resource policy belongs to the adapter.
- When changing the ACP boundary, preserve fail-closed behavior and raw unknown guards before SDK optional normalization. The protocol-error guard reads only SDK byte output; the envelope guard reads already-parsed messages. SDK types do not replace runtime validation; details of the limit and bounded EOF are in README, under "Transport and limits".
- The editor loads `dist/main.js`; unit tests import `dist/extension.js`, `dist/sessions.js`, and `dist/acp.js`. Generated bundles/sourcemaps and `node_modules/` are excluded from Git; edit source files, not `dist/`.
- Launch `opencode acp` with `shell: false`, not an HTTP client for a shared service. `opencodeNativeChat.command` is an executable path, not a command string with arguments. Preserve ACP v1, `clientCapabilities: {}`, and `mcpServers: []` for new/load.
- The participant ID, session type, and URI scheme must match: `opencode`. The extension ID for the CLI is different: `RabbitShare.opencode-native-chat` (`publisher.name` from `package.json`).
- The native participant routes Send to the same `requestHandler` as the content provider. When changing routing, check both saved resources and `opencode:/untitled-*` for the first request.
- OpenCode stores history and replays it through `session/load`; `workspaceState` stores only `id`, `cwd`, `label`, and `created`. The extension's list does not import all OpenCode sessions.
- Catalogs/confirmed selections for Model (`model`), Agent (`mode`), and Reasoning (`effort`) come from ACP new/load/set/update; pass literal values without splitting IDs or hardcoded choices. LanguageModelChat **OpenCode (configured)** is only a technical bridge, not the actual selection. Skills, MCP, and permissions remain with OpenCode. Preserve atomic raw validation before SDK normalization; a malformed update does not change the snapshot, and absent/null new/load means an empty catalog. Hide Reasoning when there are no effort choices; do not replace an unavailable currentValue with a fallback.
- The slash catalog comes from ACP `available_commands_update`, separately for each session; a malformed/over-limit update does not change the snapshot, and failure/load clears the stale list. `chatSessionCustomizationProvider` returns Prompt items only for the exact canonical REAL URI or an already-materialized alias. Generic drafts remain lazy. Virtual `opencode-command:` files contain only metadata; external/foreign/stale prompt references are rejected before the prompt, with another synchronous check after config/load waits and before history/RPC. See README, "Slash commands", for catalog limits, native names/collisions, and the checklist. Do not replace ACP commands with hardcoded TUI commands.
- In 1.140.0, the catalog is shared by session type; there is no separate per-resource catalog API. Preserve the union of unique groups for live REAL URIs: own selections are defined, foreign ones undefined; the provider returns its own `ChatSession.options`. The hidden locked `opencode_session` marker with `when: "false"` and `unconfigured` filters REAL groups through `chatSessionOption.opencode_session`. A binding belongs to the original URI; revision-scoped item IDs and observed/pending state suppress broadcast/echo and do not use the active panel/marker to select a backend record. When changing UI, read the current contract and native checklist in README; doubles do not prove reused/resource-less renderer isolation.
- The setter synchronously reserves one pending slot and checks revision/membership; an active/reserved prompt prohibits changes. Send waits for an already-accepted config operation; its failure adds no turn and sends no prompt. Stop before the prompt starts sends no cancel and does not cancel the setter. An RPC error/malformed set makes config uncertain; a fresh load is required before a future prompt, without automatically replaying old selections/tools/permissions. Preserve lock refresh after reservation and turn cleanup.
- Product New (`opencode.newSession`) selects cwd, creates one empty saved ACP session, opens the REAL URI through public `vscode.open`, then moves the same session to the sidebar through `workbench.action.chat.openInSidebar`; the original tab closes, and generation occurs only on Send. Move in 1.140.0 uses the active Chat editor; see README for native verification of moving/focus changes. The generic draft/new-item handler and untitled route remain lazy/default until materialization; activation and an undefined input query do not launch ACP.
- The top "+" in OpenCode Chat routes to Product New through the proposed `chat/newSession` menu: `1_open@0`, `chatSessionType == opencode`, Trust and workspace gating. Other session types and explicit generic draft commands retain the standard lazy route; do not launch ACP in an undefined input-state query for the sake of a picker. Verify the native primary action separately from the manifest/adapter double.
- One process serves multiple sessions; each session allows one active prompt. The deadline for an ordinary ACP request is 30 seconds; prompts have no overall deadline. A timeout closes the shared connection and process, affecting other sessions. Stop after the prompt starts sends async `session/cancel` with rejection handling; after 5 seconds, a hung connection is also closed for all its sessions.
- Preserve Workspace Trust and explicit permission choices: Escape, closing Quick Pick, and cancellation do not approve a tool. The client does not declare filesystem/terminal capabilities; the extension is not a sandbox.

## Checks

- After runtime changes: `npm test` and `npm run check`. `pretest` builds bundles; `precheck` builds them and runs `npm run check-types` (strict, no emit). Check verifies syntax and manifest/launch/tasks, but not editor compatibility.
- Before running tests directly, run `npm run build`. One file: `node --test test/extension.test.js`; one scenario: `node --test --test-name-pattern='session-type participant' test/extension.test.js`. Put runner flags before the file path.
- The user temporarily prohibited edit/Retry after the migrations: `supportsCheckpoints` remains absent/false; the shared handler rejects native Retry and inconsistent history before an ACP prompt. For approved dynamic slash suggestions, the manifest enables only `supportsPromptAttachments: true`; other attachments remain disabled. Preserve regressions for the prohibition and ordinary new Send. The historical replacement baseline was replaced with checks for the chosen contract; see README for fresh results and previous deadline failures under load. Replacement/fork remains a separate stage; selectors/slash commands do not bypass the prohibition.
- Unit tests launch a real child process, `test/fixtures/agent.cjs`, without a model, credentials, or an installed OpenCode. They replace the VS Code API with a double; this is not native UI evidence.

## Editor verification

- For manual verification, use the **OpenCode Native Chat** configuration in `.vscode/launch.json` or the CLI command from README with `--enable-proposed-api=RabbitShare.opencode-native-chat`. Both F5 configurations run **build extension** before launch; after editing, rebuild bundles first, then run **Developer: Reload Window**. Changes to runtime arguments require a full editor restart.
- Run manual checks without `--extensionTestsPath`; isolate them with `--user-data-dir` and `--extensions-dir`. Artifacts in `test/.editor-profile/` and `test/.editor-extensions/` are excluded from Git; logs may contain prompts and secrets.
- **Native API smoke test** checks activation and lazy draft open through `workbench.action.chat.openNewChatSessionInPlace.opencode` with `sidebar`, not eager Product New: no ACP or prompt. CLI extension tests use in-memory storage; the smoke test waits up to three minutes for manual Workspace Trust. Do not disable Trust or set it programmatically.
- In VS Code 1.140.0, `activeChatPanelSessionResource` returns only Local sessions. Confirm that OpenCode opened through the renderer log: `ChatWidget#firstRender: session=opencode:/…` and `[ChatViewPane] loadSession done … uri=opencode:/…`.
- `supportsAutoModel: true` unblocks Send but **does not remove** the `LanguageModelChat` requirement when converting a request in VS Code 1.140.0. `Language model unavailable` occurs before the ACP handler; do not try to fix it by reconfiguring OpenCode credentials.
- Backend responses and fixture tests do not prove native Send. An editor response, incremental streaming, real tools, approval/rejection, Stop during a response, and recovery after restart require separate observations; do not claim that the smoke test verifies them.
- Manual confirmations in README include previous builds before and after the TypeScript/SDK migrations, but all predate Model/Agent/Reasoning and eager New. Native evidence for this feature and the new smoke test is still absent; preserve historical results and verify new bundles separately. Automated GREEN does not mean release/review approval.
